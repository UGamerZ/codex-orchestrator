Automated task execution with Codex


A separate system handles Trello tasks and reviews changes before handing them to a person. Complete the server setup and connect Trello and Telegram before starting it.

New

  • Project selection. Connect an existing GitHub repository using an account with access, or create a new local project. Local development includes separate branches and reviews without GitHub. New projects can optionally be published to a private repository.
  • Task queue. The manager checks a dedicated board once an hour. Up to two executors can work at the same time.
  • Check tasks on demand. Send /check to the Telegram bot to request a board check without waiting for the schedule. The hourly schedule and executor limits stay in effect.
  • Changes ready for review. Each task produces a pull request or local branch and stays In Progress until its current changes pass review. Only then does it move to Done. People archive cards manually.
  • Review and fixes. The reviewer sends findings back to the executor for automatic fixes. Final approval and merging remain with a person.
  • Available review materials. Native reviewers can read the supplied changes and task details within their restricted working copy. These materials are kept out of published project changes.
  • Telegram questions. If an agent lacks clear requirements, data, or access, it pauses and asks a question. A reply returns to the agent that asked it.
  • More autonomous work. Agents handle routine implementation decisions themselves and ask only about genuine blockers. A task can be fully described in its card title without a separate description.
  • Answers stay with the task. Clarification history is retained during follow-up work. Repeated answered questions are retried with the saved context, and setup errors are clearly distinguished from agent questions.
  • Existing project links. Safe internal links are preserved when preparing and publishing working copies, so ordinary projects no longer stop before an executor can start.
  • Reliable automatic fixes. A delayed GitHub task list no longer mistakes the system's own published fixes for outside edits. Genuine outside changes still stop automatic publication.
  • Review grounded in current changes. Reviewers check existing safeguards and require a concrete failure scenario before requesting another fix, reducing repeated speculative findings.
  • Meaningful commit names. Each executor run names its commit after the actual changes. Corrections after review describe the specific fix instead of repeating the Trello card title.
  • Task photos and files. Agents receive local copies of Trello attachments and linked files, allowing them to inspect reference designs inside the isolated environment.
  • Read other project branches. Agents can inspect code and history from other branches and use relevant changes for their task. Those reference branches remain read-only.
  • Next tasks after completion. Moving a reviewed task to Done automatically checks To Do for the manager. New tasks can start without waiting for the hourly check; executor limits remain in effect.
  • Proportionate documentation review. Guides are reviewed for accuracy and usefulness to their intended readers. Wording preferences and unnecessary technical explanations no longer block a simple documentation task.
  • Workflow permission reaches publication. An explicit approval in reply to the executor's workflow question, including phrases such as “yes, u can”, authorizes publishing those changes for that task. Previously saved approvals automatically resume blocked publication. Other tasks remain restricted.
  • Publication recovery. Publishing retries a failed push before stopping the task. If it still fails, the system reports the cause with credentials removed.
  • Model overload recovery. Temporary model overloads are retried automatically with the same task and session, rather than being reported as an isolation failure.
  • Empty agent responses. If an agent returns an empty question, the system retries once with explicit response instructions instead of asking the user to supply unspecified resources.
  • Review feedback in Telegram. Reply to a completion notification to return an open task to In Progress. Your feedback reaches the executor, and the updated changes go through another review. The bot confirms receipt; replies to older completion messages also work.
  • Completion notifications. A task completion message is sent after review finishes without findings.
  • Isolated execution. Choose Docker or a restricted Windows environment without a virtual machine. Project working copies are separate, and agents do not receive GitHub, Trello, or Telegram management credentials.
  • English by default. The README, setup guides, system instructions, and operator messages use English. Russian documentation is available as a separate translation.
  • Short commit titles. Executor commits use at most five meaningful words describing the actual change. Detailed explanations stay in the task summary.
  • Preserve existing data. Moving settings to JSON keeps the original records and table intact. Agents must not infer permission to delete data from plans for future cleanup. Publication blocks detected destructive database operations.
  • Recover interrupted agents. Timed-out or interrupted agent runs retry automatically up to three times while retaining their work. Safety restrictions and requests for human input remain in effect.
  • Visible review blockers. When an externally changed branch needs fixes, Telegram reports the findings and explains why automatic changes have stopped, instead of leaving the task silently inactive.
  • Continue after manual branch updates. An optional setting lets system-created tasks continue after manual changes or Update branch. The latest changes are preserved, reviewed again, and extended with normal commits. Other branches stay read-only.
  • Operator dashboard. View task blockers and agent activity, answer questions, retry waiting tasks, check the board, pause scheduling, and edit runtime settings from a local browser.
  • Visible failures. Telegram reports agent and controller problems and reminds you about blocked tasks. A Windows watchdog detects a stopped controller and restarts it safely.
  • SQL comment handling. Explanatory SQL comments no longer stop publication as if they were commands that delete data.
  • Agent log viewer. Open executor and reviewer logs from the Agents page, including completed tasks, to see tool activity, results, errors, and progress messages. Credential-related content is filtered.
  • Respect completed Trello cards. Cards moved to Merged or any list outside To Do, In Progress, and Done are treated as completed. Later PR changes no longer bring them back to In Progress or restart review. This also applies after changing environments: PRs keep their connection to Trello, previous environments retain their own tasks, and late review errors do not send new blockers for completed cards.
  • Multiple working environments. Add GitHub repositories or local Git projects and switch between them in the dashboard. Each environment keeps its own tasks, branches, logs, and agent sessions. Active agents finish before switching. Environments can share the same Trello board and lists.
  • Separate GitHub accounts. Sign in through a GitHub authorization code and choose an account for each project. Telegram replies stay with their original task, including tasks in an inactive environment.
  • View saved environments. Open the settings of any added environment to see its project, GitHub account, Trello lists, models, and limits without switching or starting work.
  • Edit environments. Update saved projects, GitHub accounts, Trello lists, models, and limits from a prefilled dashboard form. When the project setup changes, the previous environment keeps its tasks and work and remains available to switch back to.
