# Установка Codex Orchestrator

[English](../../INSTALL.md)

Скачайте готовый архив из [GitHub Releases](https://github.com/UGamerZ/codex-orchestrator/releases/latest) и распакуйте в **новую приватную папку**. Внутри уже есть собранная программа: устанавливать Go или клонировать репозиторий не нужно. Папка останется местом установки, хранения настроек и истории задач.

| Архив | Платформа | Начало установки |
| --- | --- | --- |
| `*-windows-amd64.zip` | Windows, Intel/AMD x64 | Двойной щелчок по `Install.cmd` |
| `*-linux-amd64.tar.gz` | Linux, Intel/AMD x64 | `sh install.sh` |
| `*-linux-arm64.tar.gz` | Linux, ARM64 | `sh install.sh` |
| `*-darwin-arm64.tar.gz` | macOS, Apple Silicon (M-серия) | `sh install.sh` |
| `*-darwin-amd64.tar.gz` | macOS, Intel | `sh install.sh` |

Нужен именно архив с названием платформы. Автоматические архивы GitHub **Source code** не содержат готовую программу. Пакеты не имеют цифровой подписи; контрольные суммы находятся в `SHA256SUMS.txt`.

## Подготовка

Установите [Git](https://git-scm.com/downloads), [GitHub CLI](https://cli.github.com/) и [Codex CLI](https://developers.openai.com/codex/cli/). В Codex войдите через ChatGPT: API-ключи проект не поддерживает. Для GitHub-проекта нужен аккаунт с правами записи; локальные ветки можно хранить без публикации на GitHub.

Создайте доску Trello с тремя списками **To Do**, **In Progress**, **Done**. Получите ключ и токен с правами чтения и записи через <https://trello.com/power-ups/admin>. Мастер покажет доски и списки на выбор — искать их ID вручную не потребуется.

Создайте отдельного Telegram-бота через **@BotFather**. По просьбе мастера отправьте ему `/start` в личные сообщения. Другой процесс или webhook не должен забирать обновления этого бота.

Токены вводятся скрыто и сохраняются только локально. В релизах нет ваших конфигов, учётных данных и рабочих проектов.

## Windows

1. Распакуйте ZIP, например в `C:\Users\ВАШЕ_ИМЯ\Apps\CodexOrchestrator`. Не распаковывайте поверх существующей установки или в общедоступную папку.
2. Запустите **Install.cmd**. Выберите Windows-песочницу без Docker/VM либо Docker Engine в Ubuntu WSL. Если чего-то не хватает, установщик покажет причину и необходимое действие.
3. Выберите проект, базовую ветку и GitHub-аккаунт либо создайте локальный проект. Существующий конфиг можно сохранить.
4. Введите ключи Trello и Telegram, выберите доску и списки по номерам и укажите поддерживаемый вами файл авторизации Codex `auth.json`.
5. Дождитесь подготовки среды и проверки изоляции и интеграций. **Установка сама не запускает агентов.**
6. Для запуска откройте **Start.cmd** и оставьте окно работающим. Панель управления: **http://127.0.0.1:8787**. Остановка — `Ctrl+C` в окне программы.

Windows-песочница запрашивает права администратора через UAC. Используйте тот Windows-аккаунт, которому принадлежит вход в Codex. Настройка устанавливает системные сетевые ограничения песочницы и хранит среды задач в приватном каталоге `C:\ProgramData\CodexOrchestrator\instances`. Рабочие копии и состояние агентов раздельные, исполнителей одновременно до двух, но системная учётная запись песочницы общая. Подробности: [ограничения Windows-режима](../../NATIVE-INSTALL.md).

Для Docker сначала подготовьте Ubuntu WSL и работающий **Linux Docker Engine** по [инструкции](README.md#docker-installation-notes). Мастер спросит название дистрибутива. Автоматическая настройка Docker Desktop не выполняется.

После проверки настоящей задачи можно отдельно включить watchdog скриптом `scripts/Install-Watchdog.ps1 -Config config.native.json` из PowerShell администратора. Для Docker укажите `-Config config.json`. Сам мастер автозапуск не включает.

## macOS: Apple Silicon и Intel

Для Apple Silicon скачайте архив **darwin-arm64**, для Intel — **darwin-amd64**. Linux-бинарники напрямую в macOS не запускаются. Распакуйте архив в новую приватную папку внутри домашнего каталога, откройте в ней Terminal и выполните:

```sh
sh install.sh
```

Установщик использует **Colima с Docker** в отдельной VM с профилем `codex-orchestrator`. Docker Desktop не используется, активный Docker-контекст не меняется. Нужна macOS 13 или новее с поддержкой виртуализации. VM получает 4 CPU и 6 ГиБ RAM; для двух исполнителей рекомендуется 16 ГиБ RAM на Mac. Общие папки с файловой системой Mac отключены.

При необходимости установите [Homebrew](https://brew.sh/). Мастер предложит поставить недостающие зависимости после подтверждения. Либо заранее выполните:

```sh
brew install python git docker docker-compose colima gh
```

Далее мастер подключит выбранный проект, Trello, Telegram и вход Codex через ChatGPT. Сетевые правила применяются **внутри VM**, а не в macOS. До запуска задач выполняются проверки изоляции. Привилегированные контейнеры агентов не используются.

Запуск после настройки:

```sh
sh start.sh
```

Панель — http://127.0.0.1:8787, остановка — `Ctrl+C`. После перезапуска Colima повторно примените правила VM и проверьте среду:

```sh
colima start codex-orchestrator --activate=false
colima ssh codex-orchestrator -- sudo -n sh -s < scripts/network-policy.sh
sh start.sh --check
sh start.sh
```

Пакеты пока без подписи и notarization Apple. Если macOS блокирует `bin/orchestrator`, проверьте источник и контрольную сумму, затем рассмотрите разрешение запуска в **System Settings → Privacy & Security**. Установщик не отключает Gatekeeper и не снимает карантин автоматически. Go для этих архивов не нужен.

## Linux и Docker

Нужны Docker Engine, Docker Compose v2, Git, GitHub CLI, **Python 3.9+**, `iptables` и возможность вызвать `sudo` для сетевых правил. Текущий пользователь должен иметь доступ к Docker. Не запускайте весь мастер от другого пользователя: входы в GitHub и Codex принадлежат вашему аккаунту.

```sh
tar -xzf codex-orchestrator-vVERSION-linux-amd64.tar.gz
cd codex-orchestrator-vVERSION-linux-amd64
sh install.sh
```

Замените `vVERSION` версией скачанного архива; для ARM используйте `arm64`. Можно подключить GitHub-репозиторий, создать локальный проект или взять закоммиченную историю существующего локального Git-проекта. Выбранный GitHub-аккаунт и базовая ветка проверяются. В локальном режиме ветки остаются локальными; создание GitHub-репозитория доступно через панель после запуска.

Первая установка собирает Docker-образы, загружает зависимости, устанавливает правила выделенной сети агентов и проверяет интеграции. Карточки во время настройки не обрабатываются.

Для запуска:

```sh
sh start.sh
```

Оставьте процесс работающим либо настройте собственный менеджер служб. Остановка — `Ctrl+C`. После перезапуска Docker повторно примените `scripts/network-policy.sh` с правами администратора и выполните `sh start.sh --check`. Мастер не устанавливает Linux-службу и не меняет автозапуск.

Панель слушает только loopback. Для удалённой машины используйте SSH-туннель:

```sh
ssh -L 8787:127.0.0.1:8787 USER@SERVER
```

Затем откройте http://127.0.0.1:8787 на своём компьютере.

## Проверка архива и обновление

Скачайте `SHA256SUMS.txt` из того же релиза. В Windows сравните результат `Get-FileHash .\АРХИВ.zip -Algorithm SHA256` со строкой в файле. В Linux положите архивы рядом с ним и выполните `sha256sum --ignore-missing -c SHA256SUMS.txt`.

Если установка остановилась, исправьте указанную причину и запустите мастер повторно. Для смены интеграций Windows запустите `scripts/Configure-Integrations.ps1` и ответьте `n` на предложение сохранить учётные данные.

Архивы предназначены для **новой установки**, а не автоматического обновления работающей системы. Перед обновлением остановите контроллер и watchdog, сохраните резервную копию настроек, секретов и состояния и прочитайте описание релиза. Два контроллера не должны одновременно использовать одни и те же состояние, бот или очередь задач. История предыдущей установки автоматически не импортируется.

Ограничения публикации сохраняются: агенты не могут аппрувить и мержить PR, делать force-push и публиковать в базовую ветку. Публичный веб-поиск доступен, сетевые ограничения команд сохраняются.
